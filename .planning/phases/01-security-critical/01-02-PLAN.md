Create `src/lib/rate-limit.ts` — a simple, Edge-compatible rate limiter using a Map with TTL cleanup.

**Do NOT use npm packages** — Edge Runtime is restrictive. Use a plain Map-based sliding window.

```typescript
export interface RateLimitConfig {
  interval: number;   // Time window in milliseconds (e.g., 60000 for 1 min)
  maxRequests: number; // Max requests per window
}

interface RateLimitEntry {
  count: number;
  resetAt: number;
}
```

Implementation:
1. Create a `Map<string, RateLimitEntry>` as module-level state (survives across requests in same worker)
2. Export `function checkRateLimit(key: string, config: RateLimitConfig): { allowed: boolean; remaining: number; resetAt: number }`
   - If no entry or entry expired (Date.now() > resetAt): create new entry with count=1, resetAt=now+interval
   - If entry exists and count < maxRequests: increment count, return allowed=true
   - If entry exists and count >= maxRequests: return allowed=false with remaining=0
3. Add periodic cleanup: every 100 calls, iterate map and delete expired entries (prevents unbounded growth)
4. Export pre-configured limiters as constants:
   ```typescript
   export const RATE_LIMITS = {
     login: { interval: 60_000, maxRequests: 5 },
     upload: { interval: 60_000, maxRequests: 10 },
     webhook: { interval: 60_000, maxRequests: 60 },
   } as const satisfies Record<string, RateLimitConfig>;
   ```
5. Export `function getRateLimitHeaders(remaining: number, resetAt: number): Record<string, string>` that returns standard headers: `X-RateLimit-Remaining`, `X-RateLimit-Reset`

**Edge Runtime constraints to follow:**
- No `require()`, no Node.js built-in imports
- Use `Date.now()` for timing (available in Edge)
- Use `Map` (available in Edge)
- No `setInterval` or `setTimeout` for cleanup — use lazy cleanup on each call

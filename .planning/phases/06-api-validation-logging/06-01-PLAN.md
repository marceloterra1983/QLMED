  <files>package.json, src/lib/logger.ts, src/lib/api-error.ts</files>
  <action>
1. Install pino: `npm install pino`

2. Create `src/lib/logger.ts`:
   - Import pino, create logger instance with `level: process.env.LOG_LEVEL || 'info'`
   - Export named `logger` (not default export)
   - Include a `createLogger(name: string)` factory that returns `logger.child({ module: name })` for per-module loggers
   - Use `pino({ browser: { disabled: true } })` to avoid browser-side pino issues in Next.js (server-only module)
   - Add comment: module is server-only, do not import from client components

3. Create `src/lib/api-error.ts`:
   - Import `logger` from `@/lib/logger`
   - Import `NextResponse` from `next/server`
   - Export function `apiError(e: unknown, context?: string): NextResponse`:
     - If `e` is instance of Error: log `e.message` + `e.stack` at error level with context
     - If `e` is string: log it
     - Otherwise: log `JSON.stringify(e)`
     - Always return `NextResponse.json({ error: 'Erro interno do servidor' }, { status: 500 })`
   - Export function `apiValidationError(errors: z.ZodError): NextResponse`:
     - Return `NextResponse.json({ error: 'Dados invalidos', details: errors.flatten().fieldErrors }, { status: 400 })`
   - Use Portuguese for client-facing error messages (project convention)
  </action>

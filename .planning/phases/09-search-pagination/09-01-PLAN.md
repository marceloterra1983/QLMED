<task type="auto">
  <name>Task 1: Replace flexMatchAll search with DB-level WHERE ILIKE</name>
  <files>src/app/api/invoices/route.ts</files>
  <action>
Refactor the search branch (lines ~301-361) in the GET handler to use DB-level filtering instead of in-memory flexMatchAll:

1. **Remove the `take: 5000` approach** — currently loads all invoices then filters in JS.

2. **Build dynamic WHERE clause for search** — For each search word from `normalizeForSearch(search).split(/\s+/)`, add an AND group where each word must match at least one field:
   ```
   AND (
     "senderName" ILIKE '%word%'
     OR "recipientName" ILIKE '%word%'
     OR "accessKey" ILIKE '%word%'
     OR "number" ILIKE '%word%'
     OR "senderCnpj" ILIKE '%word%'
     OR "recipientCnpj" ILIKE '%word%'
   )
   ```
   Use Prisma `where` with `OR` array inside `AND` array for each word.

3. **Handle nickname search** — The current code also matches against ContactNickname shortNames. To preserve this in DB-level:
   - First, do a fast lookup: query contactNickname where shortName ILIKE any search word for this company, get back the matching CNPJs.
   - Add those CNPJs to the OR conditions: `OR "senderCnpj" IN (matchedCnpjs) OR "recipientCnpj" IN (matchedCnpjs)`.

4. **Use standard pagination** — Apply the same `skip`/`take` pattern as the non-search branch (already exists below line 377). Get `total` count with a separate `count()` query using the same WHERE.

5. **Keep cfopTag pre-filter** — When both search and cfopTag are active, include cfop IN condition.

6. **Remove flexMatchAll import** if no longer used in this file. Keep `normalizeForSearch` import (still needed for normalizing search input before ILIKE).

7. **CNPJ digit-only matching** — The current code also matches against stripped CNPJ (`replace(/\D/g, '')`). Add a condition using `REPLACE("senderCnpj", '.', '') ILIKE` or use Prisma raw for this specific part. Simpler approach: since CNPJs are stored with formatting, just include both formatted and unformatted patterns in the ILIKE. E.g., if user types "12345", match `%12345%` which works for both `12.345.xxx` and `12345xxx`.

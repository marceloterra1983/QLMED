<!-- Modelo Prisma alvo (já sem @@ignore após 11-01) -->
model CnpjCache {
  cnpj      String   @id
  data      Json
  fetchedAt DateTime @default(now()) @map("fetched_at") @db.Timestamptz

  @@map("cnpj_cache")
}

<!-- Comportamento atual a preservar (src/lib/cnpj-lookup.ts) -->
- ensureCnpjCacheTable(): cria a tabela se não existir — REMOVER inteiramente
  (a tabela já é gerenciada pelo schema Prisma desde 11-01).
- getFromDb(cnpj): SELECT data FROM cnpj_cache WHERE cnpj = $1 AND fetched_at
  > NOW() - INTERVAL '30 days' — substituir por
  `prisma.cnpjCache.findUnique({ where: { cnpj } })` seguido de checagem em
  JS: `if (!row || row.fetchedAt.getTime() < Date.now() - DB_TTL_DAYS * 86400000) return null;`
  (mantém DB_TTL_DAYS = 30 já definido no arquivo). `row.data` já vem
  desserializado como objeto (Prisma Json), não precisa de JSON.parse manual.
- saveToDb(cnpj, data): INSERT ... ON CONFLICT (cnpj) DO UPDATE — substituir
  por `prisma.cnpjCache.upsert({ where: { cnpj }, create: { cnpj, data, fetchedAt: new Date() }, update: { data, fetchedAt: new Date() } })`.
  Manter o try/catch com log.error existente ao redor da chamada.
- Export `ensureCnpjCacheTable` é usado por dois outros arquivos
  (cnpj-monitor.ts, api/contacts/cnpj-status/route.ts) — ambos precisam
  remover a chamada/import na mesma leva (Task 2), senão o build quebra.

<!-- src/lib/cnpj-monitor.ts também consulta cnpj_cache diretamente: -->
- runBatchCnpjCheck() faz `SELECT cnpj FROM cnpj_cache WHERE fetched_at <
  $1::timestamptz` para achar CNPJs com cache expirado — substituir por
  `prisma.cnpjCache.findMany({ where: { fetchedAt: { lt: staleThresholdDate } }, select: { cnpj: true } })`
  (staleThreshold hoje é uma string ISO; ajustar para Date nativo).
- CnpjMonitoring (tabela própria desta store) permanece com
  `ensureCnpjMonitoringTable()` e raw SQL intactos — fora de escopo desta
  prova de conceito (é a PRÓXIMA tabela satélite candidata para o
  followup 11b, não esta).
